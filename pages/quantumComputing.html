Quantum Computing
This is a simple quantum circuit that can compute the win probability of choosing to swap doors in the classic Monty Hall problem.

Solving the Monty Hall problem with a real quantum computer

This page was a starting point for a learning series talk I gave at AWS to illustrate how to use a lesser-known AWS service to experiment with quantum computing.

Using AWS Braket

AWS Braket is a service that abstracts away most of the work needed to run a quantum circuit on a simulated or real quantum computer. All you need to do is translate your quantum circuit schematic into function calls in the AWS Braket SDK and you can visualize and run your circuit.

Suppose I designed the following simple circuit that tests the strategy of "sticking with your first pick" in the classic Monty Hall problem (I'll explain this circuit later).

where \(R_{y}^{\alpha}\) is a block sphere rotation about the \(y\) axis by an angle \(\alpha\). To run this circuit, I can simply install the AWS Braket SDK and execute a short Python script. 

                        
        pip install amazon-braket-sdk
                        
                    
                        
        from braket.aws import AwsDevice
        from braket.circuits import Circuit
        from braket.devices import LocalSimulator
        import math

        # Pick a device, real or simulated
        device = LocalSimulator()
        # device = AwsDevice(
        #   'arn:aws:braket:eu-north-1::device/qpu/iqm/Garnet', 
        #   aws_session=aws_session)

        # Define the circuit
        quantum_circuit = (
            Circuit().ry(0, 2 * math.acos((2 / 3)**.5)).x(0)
            .ry(1, math.pi / 4).cz(0, 1).ry(1, -math.pi/4).x(1)
            .ccnot(0, 1, 2).x(0).x(1)
        )
        # Show the circuit schematic
        print(quantum_circuit)

        # Run the circuit
        shots = 1000
        output = device.run(quantum_circuit, shots=shots)

        # Process the results
        counts = output.result().measurement_counts
        win_count = 0
        for outcome, frequency in zip(counts.keys(), counts.values()):
            if outcome[0] == "1":
                win_count += frequency
        print(f"The strategy won {win_count / shots * 100:.1f}% of the time.")

The code above produced the following output. 

        The strategy won 34.3% of the time.
Designing the circuit

We need to prepare a set of qubits to represent the starting state of the Monty Hall problem. In the classic Monty Hall problem, a prize sits behind one of three doors. Let's start our circuit by creating a qubit for each door. In general, qubits can carry a superposition of two basis states, \(|0\rangle\) and \(|1\rangle\). Let the state \(|0\rangle\) represent the absence of a prize and the state \(|1\rangle\) represent the presence of a prize.

We need to prepare a register of three qubits to represent the superposition of all possible states. Importantly, we need to entagle these qubits so that the prize is always found behind exactly one door (i.e. we should never observe no prize and we should never observe prizes behind more than one door simultaneously). We will achieve this using control gates.

The circuit below takes as input a register of three qubits in the \(|0\rangle\) state and outputs a register of three qubits that has an equal probability of being in the \(|100\rangle\), \(|010\rangle\), and \(|001\rangle\) states.

The first gate (notated by \(R_{y}^{\alpha}\)) is a rotation about the \(y\) axis on the Bloch sphere by an amount \(\alpha\) given by $$ \alpha = 2\cos^{-1}\left(\sqrt{\frac{2}{3}}\right) $$ This puts the first qubit in the superposition $$ |\psi\rangle = \sqrt{\frac{2}{3}}|0\rangle + \sqrt{\frac{1}{3}}|1\rangle $$ If we were to make many observations of this qubit immediately after the \(R_{y}^{\alpha}\) gate, we'd observe \(|0\rangle\) (no prize) two thirds of the time and \(|1\rangle\) (a prize) one third of the time.

We could do the same to the second qubit, but then the two qubits would be independent of one another, and the outcome \(|11\rangle\) would be observed sometimes, but this violates the Monty Hall problem. To avoid this, we'll use a controlled Hadamard gate which allows only the \(|0\rangle\) state flip to apply the Hadamard operation to the second qubit.

If the relative, complex amplitudes of the \(|0\rangle\) and \(|1\rangle\) basis states are stacked in a vector \(\left[\begin{matrix}1 \\ 0\end{matrix}\right]\) then the Hadamard operation produces $$ \sqrt{\frac{1}{2}}\left[\begin{matrix}\ 1 & 1 \\ \ 1 & -1\end{matrix}\right]\left[\begin{matrix}\ 1 \ \\ \ 0 \ \end{matrix}\right]=\sqrt{\frac{1}{2}}\left[\begin{matrix} \ 1 \ \\ \ 1 \ \end{matrix}\right] $$ This produces the following possible observations of the two qubits together: $$ \begin{matrix} |01\rangle \text{ with probability }\frac{1}{3} \\ |10\rangle \text{ with probability }\frac{1}{3} \\ |00\rangle \text{ with probability }\frac{1}{3} \\ \end{matrix} $$ We can finish the preparation of our 3 qubit register by adding a Tofolli gate that flips the third qubit only if the first two are in the combined \(|00\rangle\) state.

This gives us the desired initial state of the Monty Hall problem: $$ \begin{matrix} |100\rangle \text{ with probability }\frac{1}{3} \\ |010\rangle \text{ with probability }\frac{1}{3} \\ |001\rangle \text{ with probability }\frac{1}{3} \\ \end{matrix} $$ We can use this qubit register as input to two quantum circuits, one that tests the strategy of keeping one's original choice of door and another that tests the strategy of swapping doors after the host opens a door.

The "stay" circuit

The circuit above actually only needs some interpretation and it can serve as our circuit to test the strategy of sticking with one's original choice even after the host opens a door. We'll assume that we always pick the door corresponding to the first qubit as our guess (I'll leave it to you to argue from symmetry that choosing any other door at that start doesn't alter our outlook on the problem). All we need to do is run our quantum circuit a substantial number of times (e.g. 1000) and observe the output state; any time we observe the first qubit in the \(|1\rangle\) state, we win the prize, and anytime we observe the first qubit in the \(|0\rangle\) state we missed the prize. As was demonstrated earlier in this article, experiments showed a win rate of about 34%, and in theory we would expect to win only when we observe the \(|100\rangle\) state, which should happen \(\frac{1}{3}\) of the time (in the limit that we play the problem and infinite number of times).

The "swap doors" circuit

There is a pretty nifty simulator I found online for small quantum circuits. This link will open the "swap" circuit above and show you the relative frequency of different outcomes.

Let me break down this circuit into its parts.

The highlighted portion of the circuit above is our three-door qubit register we created before. The purpose of this register is to properly represent the combined state of all three doors at the start of the Monty Hall problem as a quantum superposition. The downstream parts of the circuit will compute the changes on the problem state based on the host's (and our) actions. As before, the top qubit represents the door that we initially picked.

The highlighted portion evolves the superposition to handle actions that would occur if the prize is behind the third door. We entangle an ancillary qubit (just an extra qubit to help store information above the problem state) with the \(|1\rangle\) state of the third door. When the ancillary qubit is in the \(|1\rangle\) state, the host will open door two. This might not be obvious at first, but it's clearly the only option available to the host (the host cannot open door one because we've picked it and cannot open door three because the prize is behind it). Then we swap our first door qubit with the second door qubit. This represents our decision to switch to door two once the host has opened door three.

The highlighted portion above does the same thing as before but in the case that door two hides the prize, not door three. In this case, the host must open door three and we will switch to door two.

This last portions is the most complex and handles the case where the prize is behind door one. In this situation the host will have a choice of which door to open. Therefore, we will set one ancillary qubit in the \(|1\rangle\) state which represents the logical outcome that "the host will open door two or three" and this qubit will put another ancillary qubit (the logical outcome "the host chose to open door two") in an equal superposition of the \(|0\rangle\) and \(|1\rangle\) states (representing the host having no bias towards opening door two over door three). The two ancillary qubits are in the \(|11\rangle\) and \(|10\rangle\) with equal probability and we let the first state mean the host chose to open door two and the second state mean the host chose to open door three. In each case we swap with the other (prize-less) door.

The following code implements the "swap" circuit. Note that we have to replace some of the gates above with an equivalent circuit of simpler gates if we want to run on the IQM Garnet computer (since it cannot automatically implement some of the more complicated circuits we used above). For instance, we implement the controlled Hadamard with a combination of \(R_{y}\), \(\text{CNOT}\), and \(Z\) gates, and multiple Tofolli gates are needed to create the equivalent of a many-input Tofolli. 

                        
        from braket.aws import AwsDevice
        from braket.circuits import Circuit
        from braket.devices import LocalSimulator
        import math

        # Pick a device, real or simulated
        device = LocalSimulator()
        # device = AwsDevice(
        #   'arn:aws:braket:eu-north-1::device/qpu/iqm/Garnet', 
        #   aws_session=aws_session)

        # Define the circuit
        quantum_circuit = (
                Circuit()
                .ry(0, 2 * math.acos((2 / 3)**.5))
                # Controlled Hadamard
                .x(0).ry(1, math.pi / 4).cz(0, 1).ry(1, -math.pi / 4)
                # Not not Tofolli
                .x(1).ccnot(0, 1, 2).x(1).x(0).cnot(2, 3).cnot(1, 4).cnot(0, 5)
                # Controlled Hadamard
                .ry(6, math.pi / 4).cz(5, 6).ry(6, -math.pi / 4)

                .ccnot(1, 3, 7)
                .cswap(3, 2, 0)
                .ccnot(2, 4, 8)
                .cswap(4, 1, 0)
                # 3 input Tofolli
                .ccnot(1, 5, 11).ccnot(6, 11, 9).ccnot(1, 5, 11)
                # 3 input Tofolli
                .ccnot(2, 5, 11).x(6).ccnot(6, 11, 10).x(6).ccnot(2, 5, 11)
                # 2 input cswap
                .ccnot(5, 6, 11).cswap(11, 0, 2).ccnot(5, 6, 11)
                # 2 input cswap
                .x(6).ccnot(5, 6, 11).cswap(11, 0, 1)
            )
        # Show the circuit schematic
        print(quantum_circuit)

        # Run the circuit
        shots = 1000
        output = device.run(quantum_circuit, shots=shots)

        # Process the results
        counts = output.result().measurement_counts
        win_count = 0
        for outcome, frequency in zip(counts.keys(), counts.values()):
            if outcome[0] == "1":
                win_count += frequency
        print(f"The strategy won {win_count / shots * 100:.1f}% of the time.")

The code above produced the following output. 

The strategy won 66.7% of the time.

I sent this request to the IQM Garnet computer using the AWS Braket SDK. My task had to wait a while in the queue (about 8 hours) but once it ran it produced a satisfying 67% chance of winning the Monty Hall problem when choosing to swap doors. Compared to the strategy of sticking with one's original pick (with a win rate of 33%) the "swap" strategy wins twice as often.

Conclusion

The main purpose of this article was to illustrate how to use the AWS Braket SDK on a simple toy problem. However, testing strategies in a simulated environment like this is a pretty unusual application of quantum computing. The main advantage of quantum computers is the ability to run computations on the entire space of possible inputs simultaneously. For instance, Grover's algorithm can search many database keys at the same time in an index search. In our Monty Hall circuits, we only perform computation on three input states and we have to test each strategy with it's own circuit. While this technically worked, it's hard to imagine a quantum computer ever doing this faster than a GPU. Trying out a strategy in a simulation is usually a computationally fast operation (compared to searching through a large state of possible stratgies), and in the Monty Hall problem the space of all possible strategies is extremely small. Nonetheless, the compatibility between qubits and how doors behave in the Monty Hall problem are quaint and serve as a nice starting circuit for gaining experience using the AWS Braket SDK.
